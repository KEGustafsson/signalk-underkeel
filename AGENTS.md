# AGENTS.md

## General guidance

Read no-slop.md

## Purpose

This guide tells AI and human contributors how to work safely in the signalk-underkeel
repository. It is model-agnostic: map the roles below to whatever agents, modes or prompts
your tool provides.

signalk-underkeel is a Signal K server plugin that estimates under-keel clearance from S-57
chart data, water level and vessel state, and warns before the vessel reaches shoal water. A
wrong "safe" answer can put a boat aground, so safety behaviour outranks features and
performance.

## Repository profile

- **Runtime:** Node.js Signal K plugin, TypeScript under `src/`.
- **Tests:** Jest via ts-jest under `__tests__/`, with fast-check for property tests.
- **Build output:** `lib/` is generated by `tsc`; never edit it.
- **Design source of truth:** `docs/DEVELOPMENT-PLAN.md`. Check the milestone table (§8)
  before starting work, and implement the milestone in scope rather than skipping ahead.

## Safety invariants

These hold in every change. A change that weakens one needs an explicit decision recorded in
`docs/DEVELOPMENT-PLAN.md` first.

1. **Conservative spatial queries.** `minDepthOver(polygon)` never returns a depth deeper than
   any source feature intersecting the polygon plus its position-uncertainty buffer. A
   feature beyond the buffer counts by its chart position: its P(UKC < 0) weighted by
   Φ(−g/σP), or by the survey shadow Φ(−ρ(g)) of the water charted closer when that is
   less, never less than the smaller (plan §4.3, graded chart position, survey shadow).
   Covered by fast-check property tests.
2. **Monotonic risk.** A deeper draft, a lower water level, a larger position uncertainty or
   a worse chart position σ never lowers P(UKC < 0).
3. **Never silent.** Stale position, stale water level, missing index or no chart coverage
   produce `unknown`, `off` or a warning with a reason. They never produce `normal`.
4. **Unchecked is never safe.** Route legs without coverage or with unassessed survey quality
   are `unverified`, never `ok`.
5. **Own soundings only add caution.** Living-chart data may make a cell shallower without
   confirmation, never deeper.
6. **No automatic actuation.** The plugin never sends autopilot or steering commands.
7. **`notifications.grounding` means "aground".** Look-ahead warnings use
   `notifications.navigation.underKeel`.

### Safety Agent prompt

> Act as the Safety Agent. Check this diff against the seven safety invariants in AGENTS.md.
> For each one the diff touches, name the test that proves it still holds, or the missing test.
> Flag any path where stale or missing input could produce state `normal`.

### Risk Model Agent prompt

> Act as the Risk Model Agent. Implement the approved change in `src/model/` or `src/engine/`
> following plan §4.7–§4.8. Every published result must carry its explanation terms. Add
> monotonicity and threshold tests.

### Spatial Agent prompt

> Act as the Spatial Agent. Implement the ingest or index change following plan §4.2–§4.4.
> Keep the conservativeness property test green and report query cost against the §6 budget.

## Coding guidelines

- Edit `src/`, never `lib/`.
- Strict TypeScript with `noUncheckedIndexedAccess`. Explicit types at public boundaries.
- Never wrap imports in `try/catch`.
- Lifecycle cleanup is deterministic: `stop()` clears timers, unsubscribes streams and
  terminates workers.
- All units are SI on the wire (metres, seconds, radians, m/s), as Signal K requires.
- Chart data, built indexes and replay logs never go into git (`.gitignore` covers `data/`,
  `*.000`, `*.fgb`). Small synthetic fixtures go in `fixtures/`.
- Do not add runtime dependencies without a clear need; the plugin runs on Raspberry Pi and
  Cerbo GX class hardware.

## Validation

| Change area      | Validation                                                               |
| ---------------- | ------------------------------------------------------------------------ |
| Any TypeScript   | `npm run check:ts`, `npm run check:ts:tests`, targeted `npx jest <file>` |
| Spatial / engine | targeted tests plus property tests; `npm test`                           |
| Routes / deltas  | route tests with a fake router and fake `ServerAPI`                      |
| Package/release  | `npm run verify:ci-local`, then `docs/release-checklist.md`              |

`npm test` must stay hermetic and under 120 s: the Signal K plugin registry runs it with no
network and `SIGNALK_REGISTRY_TEST=1` (see `.github/workflows/plugin-test.yml`). Tests run in
`__tests__/helpers/node-realm-environment.js`. A test may make at most 20 000 `expect()` calls
(target 5 000): collect per-element checks in a property and assert once. CI fails
`npm run verify` when the test run takes over 120 s (`UNDERKEEL_TEST_BUDGET_S`). Never skip a
safety test or lower its fast-check runs for speed (plan §7, Test runtime).

If a command cannot run in your environment, record the command and the failure. Do not claim
it passed.

## Pull request expectations

- motivation and what changed;
- exact validation commands run and their results;
- which safety invariants the change touches and the tests covering them;
- follow-up work, if any.
